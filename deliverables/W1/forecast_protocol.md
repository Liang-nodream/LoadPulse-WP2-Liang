## 1. 時間與資料口徑

| 項目 | 候選設定 / 規則 |
|---|---|
| 目標 | 區域逐小時負載 MW；AEMO 原始負載欄位、聚合及區域待確認 |
| Target time | 每個目標區間起始時刻；輸出 UTC，日曆特徵按區域指定時區計算 |
| Forecast origin | 候選：目標日之前一日當地 12:00；每個當地日發布一次 |
| Horizon | target UTC − origin UTC，單位小時；一般 24 小時日為 12–35h（無 DST 轉換時） |
| Availability | 實際可得時間 <= origin；觀測區間起始不等於發布時間 |
| 更新頻率 | Pilot 候選：固定訓練模型；正式候選：每週重訓，或每日重訓作替代方案；選擇後各模型一致 |
| 訓練窗口 | 候選 expanding window；固定長度 rolling window 作替代，長度待資料期間確認 |

AEMO 時間戳可能採資料源特定時基，需先確認，不能直接假設所有區域皆採 Brisbane 時間。DST 依已確認的目標日曆時區處理，當地日可能有 23/25 小時；以 UTC 唯一識別，實際時距逐筆計算。資料源時間與日曆時間分開管理。

## 1.1 共同資料排除規則（團隊已決議：PHEIC 期間）

WHO 於 2020-01-30 宣布 COVID-19 為國際關注公共衛生緊急事件（PHEIC），於 2023-05-05 終止該狀態；2020-03-11 才定性為全球大流行。此處採 PHEIC 作為研究操作型排除區間，不宣稱疾病於 2023-05-05 消失或各地封城期間相同。

- 日期首尾均排除。實作採區域已確認之日曆時區的左閉右開區間 `[2020-01-30 00:00, 2023-05-06 00:00)`，再換算 UTC；時區口徑由資料組確認。保留疫情前及疫情後的可用資料。
- 所有真實資料實驗（主階梯、M_AR、seasonal-naive 及形式控制）先套用同一排除遮罩，再進行 Development / Calibration / Confirmation 切分。被排除的觀測不得參與訓練、調參、插補、校準、歷史負載特徵、天氣觀測型特徵或正式評估。
- 保留原始資料與實際時間戳；排除屬研究樣本選擇，不覆寫原始檔，也不將跨越排除區間的資料視為連續時序。不得補出疫情期間資料，不得跨缺口插值、前向填補或進行位置式 lag。
- 趨勢使用真實經過時間，不將三年缺口壓縮。Lag / seasonal-naive 依真實時間戳對齊，若參照落在排除區間則標記不可用。Rolling-origin 使用實際時間與發布時點；無合格歷史或特徵則保留無效列，不能借用未來資料。
- 預測目標若在排除區間，不進入正式目標網格。若保留目標的 origin 落在排除區間（例如 2023-05-06 的前日中午），仍不得使用任何被排除的觀測；是否額外排除該 origin 為候選，須在實驗前共同凍結並套用至所有模型。
- 切分比例依排除後的合格資料規劃，另報各階段實際日期、有效筆數與季節覆蓋；跨缺口的評估窗口、連續失效事件及統計區塊不得直接拼接。疫情前後可能仍有結構差異，建議按時期另報描述性指標，是否分期建模列為候選。固定長度窗口應以實際日曆時間定義，而非排除後的列數；expanding window 可保留兩段合格歷史，但不得假設兩段結構相同。
- 合成資料不代表真實疫情：現有 2023 合成 Pilot 可完整保留作工程測試，但不得用於正式推論。新增遮罩邊界與跨缺口 lag 測試；如需驗證正式流程，可另對合成資料套用相同遮罩。

WHO 來源：[COVID-19 pandemic](https://www.who.int/europe/emergencies/situations/covid-19/)；[WHO Director-General, 5 May 2023](https://www.who.int/news-room/speeches/item/who-director-general-s-opening-remarks-at-the-media-briefing---5-may-2023)。排除規則是團隊研究決議，並非 WHO 對電力資料的處理建議。

### 排除規則的邊界測試

| 當地目標時間 | 預期處理 |
|---|---|
| 2020-01-29 23:00 | 保留（仍需符合其他品質規則） |
| 2020-01-30 00:00 | 排除 |
| 2023-05-05 23:00 | 排除 |
| 2023-05-06 00:00 | 保留候選；另檢查 origin 規則 |
| 2023-05-06 00:00 的 24h lag | 不可用：參照 2023-05-05 00:00 落在排除期（無 DST 轉換示例） |

原始資料先統一時間口徑，再套用遮罩；不得以疫情期間觀測值作為其他時期的插補或平滑來源。

## 2. Development / Calibration / Confirmation

按時間先後切分，禁止隨機 shuffle。候選比例 60/20/20（以排除 PHEIC 後的合格樣本規劃，實際日期與季節覆蓋依資料確認後凍結）；保留足夠歷史以建立週期與假日模型。所有區間採左閉右開。

| 階段 | 用途 | 禁止事項 |
|---|---|---|
| Development | 內部時間序列驗證、選特徵、選 Ridge/GAM 參數及更新策略 | 使用 Calibration / Confirmation 結果選參數 |
| Calibration | 在已鎖定模型規則下取得樣本外誤差，供統計組校準候選門檻及方法 | 依 Confirmation 回頭改門檻或模型 |
| Confirmation | 按凍結協議產出樣本外預測與配對損失 | 事後刪除困難時段、重選特徵或調參 |

邊界需依 origin 和發布時間再檢查：訓練標籤須於本次擬合時已知；用於校準的標籤須於第一個 Confirmation origin 前可得。跨邊界尚未發布的列不得用於擬合/校準，記錄排除原因與數量。若固定模型與線上更新方案不同，分開實驗，不混報。

## 3. Rolling-origin 執行流程

1. 依區域日曆建立共同 target/origin/horizon schedule；先依共同 PHEIC 排除規則建立合格目標網格，不因模型缺值而縮減；排除區間另存 audit log。
2. 依時間順序走訪 origin；按預定更新頻率擬合模型。訓練資料只用已發布的歷史標籤，歷史訓練特徵亦需符合其模擬 origin 的資訊條件。
3. 依各模型白名單產生特徵，檢查 source availability；正規化、插補、編碼器及其他學習型轉換只在允許的訓練資料擬合。
4. 對同一 origin 的全部目標預測，凍結 prediction 與模型版本；不得使用同日後續真值修補多步預測。
5. 目標觀測發布後才附加 actual，計算 residual/loss；缺失保留列及 quality_flag。
6. 以共同鍵配對模型，報告完整目標數、有效數、配對數及排除原因；輸出實驗 metadata。

固定參數下，若正式採滾動重訓，可使用 origin 前已發布的較早 Confirmation 標籤，前提是事先凍結更新規則並標示為 prequential 評估；不能用其表現重新選參數。固定模型方案不使用這些標籤重訓。

## 4. 超參數與比較控制

- Ridge 候選 alpha：0.1、1、10、100；目前程式 alpha=1 為 Pilot 固定值。
- Development 內採時間順序 rolling-origin 驗證；候選選擇指標為 MAE（RMSE 輔助），同一資訊階梯比較使用相同驗證窗口與調參預算。
- GAM 候選的平滑參數、基底數與交互項只在 Development 選擇。M0-add / M0-int 使用相同資訊集合。
- 季節 naive 不調整參照規則來迎合 Confirmation；候選參照為前週同一當地時刻且已發布之負載。
- 天氣部署版使用可追溯 issue/availability 時間的歷史預報；回顧版實際天氣獨立實驗。實際天氣不能作 day-ahead 可得性通過的證據。

### Lag 可得性例（候選 Brisbane 無 DST、區間長 1h、發布延遲 0h）

假設 origin 為 11/1 12:00，預測 11/2；11/2 00:00 的 lag24 指向 11/1 00:00，已於 01:00 可得；11/2 12:00 的 lag24 指向 11/1 12:00，13:00 才可得，因此不可用。lag48/168 在此假設下通常可得，但仍須逐筆檢查真實發布延遲與缺值。禁止直接以 `shift(24)` 代替檢查。若採前一週同一當地時刻的 seasonal-naive，須按日曆時間找參照；不得將 DST 轉換日的 168 小時位移直接等同一週前當地同時刻。
